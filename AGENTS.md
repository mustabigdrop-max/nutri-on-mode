# Architecture rules

- Social ON and PRISM load creator identity and calibration server-side using the authenticated caller ID and share creatorScriptRules; this prevents cross-user personalization and conflicting script limits.
- All vertical script generators use shared retention planning before drafting within the same generation, adding planning metadata without replacing existing result fields; this preserves the UI contract and avoids a second billed request.
- Store creator voice and measured content calibration in social_profile.creator_profile, keeping absent values null; this preserves existing profiles without fabricated performance data.
- Vertical script results include literal timed speech mapped to existing text fields; the shared retention critic counts words server-side and revises only mapped weak blocks for at most two rounds, preserving result contracts and displaying critique history rather than hiding low scores.- Retention feedback computes predicted-vs-real alignment and drops in code, confirms a creator pattern only after 3 distinct videos, and writes only confirmed patterns to creator_profile; this keeps model hypotheses from becoming fabricated calibration.
- The Studio Retention Engine (gerar_reel) streams step events while running Architect, Writer and Critic as separate JSON passes with prompts isolated in _shared/retentionPrompts.ts (re-exported by gerar_reel/prompts.ts), injects creator_voice and retention_patterns into every pass, reuses the shared critic normalization, and saves to retention_scripts; this keeps prompts swappable and scores consistent with other script tools.
- The calibrar function compares predicted vs real per retention_scripts block in code, counts each reel once per pattern in retention_patterns (confirmed only at 3+ videos), and keeps its system prompt isolated in calibrar/prompts.ts; recalibrating the same reel never inflates samples.
- Hook formula stats (creator_formula_stats) are recomputed in calibrar from saved retention_results per reel, and gerar_reel restricts the Architect to allowed formula ids, forcing an untested formula every third reel; this keeps ranking honest and exploration guaranteed in code.
- The Social ON Command Center reads only the caller's own retention data (scripts, results, formula stats, creator_goals) and computes Content Score, streak, alerts and 90-day progress in src/lib/retentionEngine.ts; empty data shows '—' instead of samples, so nothing is fabricated.
- Command Center automation runs from one hourly scheduler call to cc_automation, authenticated by the private key in cc_job_state (also accepted by gerar_reel with x-user-id). It uses a single-flight lease, small per-run batches, claims each user's day before working, retries once and logs to cc_automation_runs. Outputs stay 'pronto_para_revisar' in cc_briefings; this prevents duplicate generations and any automatic publishing.
- The Reel Factory (reel_factory) runs batches in bounded 4-idea chunks with a per-batch lease, self-chaining under a hop budget plus an hourly backstop; ideation, Architect and Writer use a lighter model while the Critic keeps gerar_reel's model, with one rewrite round. Allocation, pre-filter, originality and theme dedup live in reel_factory/logic.ts. Shared prompts live in _shared/retentionPrompts.ts (gerar_reel/prompts.ts re-exports) because functions cannot import sibling folders. Choosing a reel copies it into retention_scripts so calibration learns from it; this keeps cost bounded and nothing published without approval.

- The Reel Factory content matrix (content_pillars per user, global content_angles, content_cases) drives batch slots via allocatePillars/assignAngles in reel_factory/logic.ts; pillar and pillar x angle performance is computed on read from reel_bank + retention_results, never stored, so the Matriz heatmap and the allocator always agree with real data.
- The Cut Generator renders data/text/diagram cuts on canvas client-side (no image model) and only illustration cuts go through gerar_corte, which enforces chosen-reel gating, content blocklist, daily limit, prompt cache and regen cap server-side; text is always drawn by code over images.
- Curated pillar reels are seeded from versioned templates (script_templates, loaded by seed_pilar) into the caller's retention_scripts via a SECURITY DEFINER upsert keyed by (user_id, slug); source checks write only through mark_fonte_conferida, so reseeding never duplicates and users cannot edit script content directly.
