# Architecture rules

- Social ON and PRISM load creator identity and calibration server-side using the authenticated caller ID and share creatorScriptRules; this prevents cross-user personalization and conflicting script limits.
- All vertical script generators use shared retention planning before drafting within the same generation, adding planning metadata without replacing existing result fields; this preserves the UI contract and avoids a second billed request.
- Store creator voice and measured content calibration in social_profile.creator_profile, keeping absent values null; this preserves existing profiles without fabricated performance data.
- Vertical script results include literal timed speech mapped to existing text fields; the shared retention critic counts words server-side and revises only mapped weak blocks for at most two rounds, preserving result contracts and displaying critique history rather than hiding low scores.- Retention feedback computes predicted-vs-real alignment and drops in code, confirms a creator pattern only after 3 distinct videos, and writes only confirmed patterns to creator_profile; this keeps model hypotheses from becoming fabricated calibration.
- The Studio Retention Engine runs Architect, Writer and Critic as separate JSON passes in one edge function with prompts isolated in retention-engine/prompts.ts, reuses the shared critic normalization, and saves each generation to reel_generations; this keeps prompts swappable and scores consistent with other script tools.
